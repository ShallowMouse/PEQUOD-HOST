# PEQUOD engine

The Rust source of every PEQUOD plugin (the same code the VST3 versions are
built from), plus `pequod_engine`, which bundles them all into one static
library that PEQUOD Host links in. In the host they run natively: no VST3
files, no scanning, panels drawn by the host, and settings saved by the VST3
versions load into them.

Build (Windows, before CMake; the workflow does this):

    cargo build --release -p pequod_engine --target x86_64-pc-windows-msvc

with `RUSTFLAGS=-C target-feature=+crt-static` (the host uses the static C
runtime). CMake picks up
`engine/target/x86_64-pc-windows-msvc/release/pequod_engine.lib`.

- `vintage/` is the shared framework (DSP, panels, the plugin macro).
  `vintage/src/native.rs` is the engine side of every plugin.
- Each collection is a folder of plugin crates.
- `pequod_engine/` is generated by `engine_gen.py` from the workspace members;
  its C interface is `Source/PequodEngineApi.h` in the host.
- The VST3 versions are built from the same crates without the `engine`
  feature (each crate is a `cdylib`).
